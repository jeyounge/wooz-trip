# 장소 데이터 수집 계획 (전국)

> 2026-10-17 결정. 매일 자동으로 돌고, **LLM 토큰을 쓰지 않는다** (수집·변환·DB 반영 모두 규칙 기반 코드).
> 실행 방법은 `docs/real-data.md`, 이 문서는 무엇을 어떤 순서로 모으는지.

## 1. 원칙

| 한다 | 안 한다 |
| --- | --- |
| 공식 API·공공데이터(TourAPI 등)를 받아 저장 | 네이버·카카오 지도/플레이스/블로그 화면 자동 수집 |
| 사실 정보(영업시간·휴무·주차·유모차·수유실·아기의자·홈페이지 링크) 저장 | 리뷰·후기·사진·별점 저장 |
| 네이버·카카오는 화면에 **검색 링크**로만 연결 | 검색 API 결과를 DB 로 쌓기 |
| 승인은 사람이, 아이 태그 보완은 운영자 확인 + 사용자 제보 | AI 로 후기 요약해서 정보 만들기 |

**네이버 블로그·후기에서 정보를 뽑아 저장하지 않는 이유**
- 네이버 검색 API(블로그 포함)는 2026-09 개정 약관에서 "검색 결과를 그대로 보여주는 용도"로 좁혀졌고,
  AI 요약·자동 수집이 금지 항목이라고 보도됐다. 2026-07-31부터 신규 신청도 막혔다 (원문 약관은 개발자센터에서 재확인 필요).
- API 없이 블로그 페이지를 긁으면 약관 위반이고, 크롤링이 데이터베이스권 침해로 인정된 판결도 있다 (네이버 부동산 사건 1심).
- 후기에서 뽑은 내용이 "사실"이어도 수집 방법이 문제가 된다. CLAUDE.md 9장 원칙과도 충돌한다.

| 출처 | 얻는 것 | 상태 |

| TourAPI 무장애 여행정보 | 유모차·수유실·아기의자 | **적용** (일부 장소만 있음) |

| 사용자 제보 + 여행 후 짧은 질문("아기의자 있었나요?") | 아이 태그 보완 | 제보는 있음, 질문은 다음 단계 |

## 3. 지역 순서와 자동 일정

`src/lib/areas.js` 순서: **제주 → 인천 → 경기** → 서울 → 강원 → 부산 → 경남 → 경북 → 전남 → 전북 → 충남 → 충북 → 대구 → 광주 → 대전 → 울산 → 세종

매일 00:10 (윈도우 작업 스케줄러 "wooz-trip TourAPI daily" → `scripts/tourapi/daily.cmd`)
1. `collect auto` — 앞 지역부터: 목록(30일마다) → 소개정보 → 공통정보 → 무장애. 앞 지역을 다 받아야 다음 지역.
   목록의 수정일이 바뀐 장소만 다시 받는다 (한 번 다 받은 뒤에는 하루 호출이 크게 줄어든다).
2. `build` — 받은 지역 전부를 장소 행으로 변환 (`data/build/<지역>.json`)
3. `import` — 지난번과 달라진 장소만 DB 에 **후보**로 반영. 승인·제외했거나 운영자가 고친 장소는 내용을 덮어쓰지 않는다.

## 4. 호출 한도와 기간

- 개발계정: API 별 **하루 1,000회** (스크립트는 950회에서 멈춤). 장소 1곳 = 소개 1회 + 공통 1회 (+ 무장애 일부).
- 제주(약 1,500곳): 남은 호출 약 2,100회 → **약 3일**.
- 인천·경기·전국: 각 지역 목록을 받으면 정확한 수가 나온다. 전국은 수만 곳이라 개발계정으로는 몇 달 걸린다.
  → 제주를 다 받은 뒤 data.go.kr 에서 **운영계정(트래픽 증가)**을 신청한다 (활용사례 등록 필요, 심의 승인).
  승인되면 `.env.local` 에 `TOURAPI_DAILY_LIMIT=` 를 그 한도에 맞춰 올린다.

## 5. 서비스에 지역을 여는 순서

수집과 서비스 오픈은 따로 간다. 다른 시·도 장소는 `region = 시·도 이름(incheon 등)`, 후보 상태로 쌓아 둔다.

| 단계 | 할 일 |
| --- | --- |
| 1. 제주 (지금) | 300곳 승인 → AI 루트 → 샘플 지우기 |
| 2. 인천·경기 | 권역 나누기(예: 인천 강화·영종·시내, 경기 남부·북부·동부) → `config.js` REGIONS 를 시·도별로 확장 → 지역별 승인 → AI 루트 |
| 3. 전국 | 같은 방식으로 시·도별 오픈. 승인 장소가 수천 곳이 되면 장소 조회를 지역별로 나누고(지금은 승인 장소를 한 번에 읽음) PostGIS 검토 |

## 6. 운영자 일

- `/admin` → 장소: 시·도 고르기 → 필터(확인 필요 / 아이 태그 없음 / 영업시간 없음) → 선택 승인·제외.
  열면 TourAPI 원문과 **공식 홈페이지 링크**가 보여서 아이 시설을 바로 확인할 수 있다.
- 매일 로그 확인은 필요 없다. 이상하면 `data/raw/tourapi/daily.log` 를 본다 (Claude 에게 "수집 로그 봐줘").
