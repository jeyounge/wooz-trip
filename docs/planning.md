# 여행 루트 서비스 초기 기획서

Oct 16, 2026 · @제키\_우제영

## 한 줄 요약

검증된 지역 장소 DB에서 시간대별로 장소를 고르면 이동 동선과 타임라인이 자동으로 그려지는 여행 루트 서비스로, 제주 아이 동반 여행에서 시작한다.

서비스명은 미정(가칭)이다. 사용자는 지역·날짜·동행 유형만 정하고, 슬롯(오전 볼거리 → 점심 → 오후 → 카페 → 저녁)을 채우거나 AI에게 빈칸을 맡긴다. 완성된 루트는 공유되고, 다른 사용자는 동행 유형별로 루트를 찾아 그대로 복사해 내 일정으로 쓴다.

## 문제 정의와 타깃 사용자

여행 일정을 짜려면 블로그·네이버 카페를 수십 개 뒤지고, 찾은 장소를 메모장이나 지도 앱에 옮겨 이동시간을 직접 맞춰야 한다. 특히 아이 동반 여행은 아기의자·주차·유모차·휴무일 같은 정보가 결정적인데, 이런 정보는 후기 곳곳에 흩어져 있다.

| 대상 | 핵심 고민 | 우선순위 |
| --- | --- | --- |
| 영유아·초등 자녀 동반 가족 | 아이 편의시설, 낮잠·식사 시간에 맞춘 동선 | 1순위 (MVP 타깃) |
| 부모님 동반 | 도보 거리, 계단, 휴식 공간 | 2순위 |
| 연인 | 분위기, 사진 명소 | 3순위 |
| 친구끼리 | 가성비, 활동형 장소 | 3순위 |

1순위를 아이 동반 가족으로 두는 이유는 정보 탐색 비용이 가장 크고, 같은 장소 DB를 근교 나들이 큐레이션('아이랑 오늘 뭐하지?' 구상)과 함께 쓸 수 있기 때문이다.

## 핵심 기능 (MVP 범위)

MVP는 제주 한 지역, 장소 200\~300곳, 아래 7개 기능으로 출시한다.

| 기능 | 내용 | MVP 포함 |
| --- | --- | --- |
| 장소 DB 탐색 | 맛집·볼거리·카페를 지역·카테고리·아이 태그로 필터 | 포함 |
| 슬롯형 루트 짜기 | 일자별 슬롯에 장소를 골라 넣으면 앞뒤 이동시간 자동 표시 | 포함 |
| 루트 시각화 | 지도 위 일자별 색상 동선 + 시간 타임라인 | 포함 |
| AI 빈칸 채우기 | 일부 슬롯만 고르면 나머지를 DB 안에서 추천 | 포함 |
| 루트 공유·복사 | 링크 공유, 남의 루트를 내 일정으로 복사 후 편집 | 포함 |
| 동행 유형 카테고리 | 아이들과·부모님과·연인·친구 루트 모아보기 | 포함 |
| 사용자 제보 | 휴무·정보 변경·아이 태그 제보 | 포함 |
| 업체 직접 등록 | 사장님이 정보 수정·홍보 | 2단계 |
| 숙소·렌터카 제휴 연결 | 루트 안에서 예약 링크 | 2단계 |

장소마다 붙는 아이 태그(예: 아기의자, 유아 메뉴, 주차, 유모차 가능, 발 씻는 곳, 정기휴무)가 범용 플래너와의 핵심 차이다.

## 사용자 흐름

새 루트를 만드는 경우와 남의 루트를 가져오는 경우 두 갈래로 시작해, 같은 편집 화면에서 합류한다.

1. 여행 기본 정보 입력: 지역(제주 서쪽 등), 날짜, 동행 유형, 숙소, 항공편 시간
2. 시작 방법 선택
   - 직접 짜기: 빈 슬롯에서 시작
   - 루트 둘러보기: 동행 유형별 인기 루트 → "내 일정으로 복사"
   - AI에게 맡기기: 조건만 넣고 초안 생성
3. 슬롯 채우기: 슬롯을 누르면 주변·시간대에 맞는 후보가 아이 태그와 함께 뜬다
4. "루트 짜기" 실행: 이동시간 계산, 지도 동선과 타임라인 생성, 휴무·영업시간 충돌 경고
5. 다듬기: 순서 드래그, 장소 교체, 메모(예: 모래놀이 장난감 챙기기) 추가
6. 저장·공유: 가족에게 링크 공유, 원하면 공개 루트로 등록
7. 여행 후: 장소 평가와 정보 제보 → 다음 사용자의 추천 품질에 반영

## 데이터 확보 전략

장소의 뼈대는 공식 API·공공데이터로 자동 수집하고, 차별화 정보는 운영자 검수와 사용자 제보로 쌓는 반자동 방식을 쓴다. 네이버·카카오 지도 화면의 자동 대량 스크래핑은 하지 않는다.

| 출처 | 가져오는 정보 | 방식 | 확인 필요 |
| --- | --- | --- | --- |
| 카카오 로컬 API / 네이버 지역 검색 API | 이름, 주소, 좌표, 전화, 카테고리, 장소 ID | 키워드 검색 자동 수집 | 결과의 DB 장기 저장 허용 범위 |
| 한국관광공사 TourAPI | 관광지 소개, 사진, 운영 정보 | 자동 수집 | 공공누리 유형별 상업 이용 조건 |
| 운영자 검수 | 아이 태그, 휴무, 소개 문장 | 관리자 화면에서 승인·체크 | - |
| 사용자 제보 | 정보 변경, 태그 추가 | 앱 내 제보 → 검수 후 반영 | - |
| 업체 직접 등록 (2단계) | 메뉴, 영업시간, 홍보 | 사장님 계정 | - |

- 리뷰, 사진, 별점, 블로그 후기는 저장하지 않고 원본 링크로만 연결한다.
- 블로그·카페는 "많이 언급되는 곳"을 찾는 사람의 참고용으로만 쓴다.
- 관리자 화면: 후보 카드 → 승인/제외, 태그 체크박스, LLM이 태그·메모로 소개 초안 작성. 한 곳당 3\~5분, 300곳에 15\~25시간 예상(추정).
- 갱신: 영업 여부·휴무는 분기별 재확인 + 제보 상시 반영. 장소 쌍별 이동시간은 캐싱해 길찾기 API 비용을 줄인다.

## AI 추천 설계

AI는 우리 DB 안의 장소만 고르고, 제약 조건은 코드가 먼저 걸러서 "없는 맛집"이나 "휴무일 방문"이 나오지 않게 한다.

1. 후보 필터(코드): 지역·반경, 날짜의 요일 휴무, 영업시간, 동행 유형 태그로 후보를 좁힌다
2. 동선 계산(코드): 캐싱된 이동시간으로 슬롯별 가능한 조합과 총 이동시간을 계산한다
3. 선택과 설명(LLM): 후보 조합 중 사용자 조건에 맞는 것을 고르고, 추천 이유를 한두 문장으로 쓴다
4. 검증(코드): 결과가 DB의 장소 ID인지, 시간 충돌이 없는지 확인 후 표시한다

동행 유형별 규칙 예시: 아이 동반은 낮잠 시간대에 긴 이동 배치, 식사 시간 고정, 실내 대안 1곳 준비. 부모님 동반은 도보 거리와 계단 최소화.

추천 모드는 "빈칸 채우기"를 기본으로 하고 "전체 초안"은 보조로 둔다. 일부를 직접 고른 루트가 만족도가 높을 것으로 보지만(추정), 출시 후 두 모드의 루트 저장률로 검증한다.

## 경쟁 환경과 차별점

범용 일정 플래너는 이미 많으므로, 동행 유형별로 검수된 장소 정보와 그대로 복사해 쓰는 루트로 차별화한다. 아래 경쟁 서비스 정보는 별도 조사 없이 작성한 것으로, 현재 기능은 확인이 필요하다.

| 서비스 | 강점 | 우리의 차이 |
| --- | --- | --- |
| 트리플 | 여행 콘텐츠, 일정 플래너, 예약 연계 | 아이 태그 등 동행 유형별 검수 정보 |
| 마이로 등 AI 일정 플래너 | 조건 입력 후 일정 자동 생성 | 우리 DB 안에서만 추천, 휴무·영업시간 검증 |
| Wanderlog (해외) | 지도 기반 일정, 협업 편집 | 국내 장소 정보 깊이 |
| 네이버·카카오 지도 저장 리스트 | 압도적 장소 데이터, 이미 쓰는 앱 | 시간 슬롯·동선 계산, 루트 단위 공유 |
| 블로그·네이버 카페 | 생생한 후기, 신뢰 | 정리된 루트를 바로 내 일정으로 복사 |

## 수익 모델

초기에는 무료로 사용자와 루트를 모으고, 트래픽이 쌓이면 구독(편의 기능)·업체 광고·예약 제휴 수수료 세 축으로 수익을 낸다.

| 수익원 | 내용 | 시작 시점 | 유의점 |
| --- | --- | --- | --- |
| 프리미엄 구독 | 루트 저장 한도 초과, 남의 루트 복사·편집, AI 추천 무제한, 오프라인 저장 | 출시 3\~6개월 후 | 무료 한도를 너무 낮추면 공유가 줄어든다 |
| 인기 추천 루트 | 열람은 무료, 복사·편집을 유료 기능에 포함 | 구독과 함께 | 열람 자체 유료화는 신규 유입을 막을 수 있다 |
| 업체 광고 | 슬롯 후보 상단 노출, 지역 특집 | DB 지역 내 업체 수 확보 후 | "광고" 표시 의무(표시광고법), 추천 신뢰 유지 |
| 예약 제휴 | 숙소·렌터카·액티비티 예약 링크 수수료 | 2단계 | 제휴사 계약 조건 확인 |

## 리스크와 확인 필요 사항

가장 먼저 풀어야 할 것은 데이터 이용 권리이고, 그다음은 초기 콘텐츠 부족(콜드스타트)이다.

| 리스크 | 대응 |
| --- | --- |
| 데이터 수집의 법적 문제 | 공식 API·공공데이터만 사용, 오픈 전 데이터 수집 방식 법률 자문 |
| 콜드스타트 (볼 루트가 없음) | 운영자가 제주 아이 동반 루트 20\~30개를 직접 제작, 본인 가족 여행 루트를 첫 콘텐츠로 |
| 정보 노후화 (폐업·휴무 변경) | 분기별 재확인, 제보 보상(예: 구독 기간 연장) |
| 길찾기 API 비용 | 장소 쌍별 이동시간 캐싱 |
| 낮은 방문 빈도 (여행은 1년에 몇 번) | 근교 나들이 큐레이션과 장소 DB 공유로 평소 방문 유도 |

- [ ] 길찾기 API(카카오모빌리티, T맵 등) 요금과 호출 한도
