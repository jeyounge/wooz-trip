# 실데이터 채우기 (장소)

> 결정 (2026-10-17): 장소 후보는 **한국관광공사 TourAPI**(공공데이터, 이용허락범위 제한 없음)로 모으고,
> Claude가 우리 형식으로 정리한 뒤, 운영자가 `/admin`에서 승인한다. 아이 태그는 운영자 확인 + 사용자 제보로 채운다.
> 카카오·네이버 데이터는 약관 확인 전이라 저장하지 않는다 (지도 검색 링크만).

## 전체 흐름

```
TourAPI ──collect──▶ data/raw/tourapi (원본 캐시, git 제외)
        ──build────▶ data/tourapi-review.json (요약·확인 필요 목록)
                     supabase/data/tourapi_places_N.sql (후보로 넣는 SQL)
        ──SQL 실행──▶ wooz_trip_places (status = candidate)
        ──/admin───▶ 승인 (목표 300곳) → AI 루트 만들기 (docs/ai-routes.md) → 샘플 지우기
```

## 1. 인증키 받기 (사용자)

[공공데이터포털](https://www.data.go.kr)에서 아래 2개를 **활용신청** (개발계정은 자동 승인, 무료).

| API | 쓰는 곳 |
| --- | --- |
| 한국관광공사_국문 관광정보 서비스_GW | 장소 목록, 영업시간·휴무·주차·유모차·놀이방 |
| 한국관광공사_무장애 여행 정보_GW | 유모차·수유실·유아용 보조의자 |

마이페이지 → 인증키의 **일반 인증키(Decoding)**를 `.env.local`의 `TOURAPI_SERVICE_KEY=`에 넣는다. 두 API는 같은 키를 쓴다.

## 2. 수집 (스크립트)

```bash
npm run tour:collect -- probe      # 응답 필드 확인 (약 10회). 처음 한 번 — 결과를 Claude 에게 보여주면 변환기를 맞춘다
npm run tour:collect -- list       # 제주 관광지·문화시설·레포츠·음식점 목록 (약 20~40회)
npm run tour:collect -- detail     # 장소마다 영업시간·휴무 (장소당 1회)
npm run tour:collect -- withtour   # 무장애 정보가 있는 곳만 유모차·수유실·유아의자
npm run tour:collect -- status     # 진행 상황
```

- **개발계정은 API마다 하루 1,000회.** 스크립트가 하루 950회에서 멈추고, 다음 날 같은 명령을 다시 실행하면
  받은 것은 건너뛰고 이어서 받는다. 제주 장소가 2천 곳 안팎이면 `detail`은 2~3일 걸린다.
  빨리 하려면 data.go.kr에서 운영계정(트래픽 증가)을 신청한다.
- `detail`은 관광지 → 문화시설 → 음식점 → 레포츠 순서로 받는다. `--max 200`처럼 나눠 받을 수 있다.
- 지역 필터가 0건이면 `.env.local`에 `TOURAPI_REGION=areaCode=39`를 넣는다 (probe가 둘 다 확인해 준다).

## 3. 정리 (스크립트 + Claude)

```bash
npm run tour:build
```

| 바꾸는 것 | 규칙 |
| --- | --- |
| 종류 | 관광지·문화시설·레포츠 = 볼거리, 음식점 = 식당, 음식점 중 카페 분류·이름 = 카페 |
| 지역 | 주소 읍면: 서쪽 = 애월·한림·한경·대정 / 동쪽 = 조천·구좌·우도·성산·표선 / 서귀포 = 서귀포시 동 + 안덕·남원 / 제주시 = 제주시 동 |
| 영업시간 | "09:00~18:00 (입장마감 17:00)", "평일/주말", "라스트오더" → 요일별 시간. 계절별·브레이크타임은 표시만 |
| 정기휴무 | "매주 월요일", "월·화요일" → 요일. "매월 첫째 주", "부정기"는 요일로 넣지 않고 표시 |
| 아이 태그 | 공식 항목만: 주차, 유모차, 놀이방(키즈존), 수유실, 유아 의자 + 정기휴무 |
| 넣지 않는 곳 | 골프·유흥·숙박·폐업 표시 등 가족 여행과 먼 곳, 제주 밖·좌표 없음 |

- 못 바꾼 것은 `source_data.flags`에 남는다 (`/admin`에 "확인 필요"로 보임).
  원문 글도 `source_data`에 같이 들어가서 운영자가 보고 고칠 수 있다.
- **Claude 정리 단계**: `data/tourapi-review.json`을 Claude 에게 보여주면, 표시가 남은 곳의 원문을 읽고
  영업시간·휴무를 고친 보정 파일을 만들어 같은 SQL에 반영할 수 있다 (API 키 불필요).

## 4. DB에 넣기 (사용자)

`supabase/data/tourapi_places_1.sql`, `_2.sql` … 을 SQL Editor에서 **순서대로** 실행한다 (400곳씩 나뉨).

- 모두 **후보**로 들어간다. 서비스 화면에는 승인한 곳만 보인다.
- 다시 실행해도 안전: 같은 장소는 덮어쓰고, **이미 승인·제외한 곳은 내용을 바꾸지 않는다** (원문만 새로 고침).
- `source_data` 컬럼이 없으면 SQL이 알아서 만든다.

## 5. 승인 (운영자, `/admin` → 장소)

- 필터: 지역 · 종류 · "확인 필요 표시 / 아이 태그 없음 / 영업시간 없음" · 검색
- 여러 곳 골라 **선택 승인 / 선택 제외**, 하나씩 열어 시간·태그 고치고 저장
- 열면 **TourAPI 원문**(영업시간·휴무·유모차·수유실 등 원래 글)이 위에 보인다
- 목표 300곳: 볼거리·체험 120 · 식당 120 · 카페 60, 지역 4곳에 고르게
- 아이 태그(유아 메뉴·좌식·발 씻는 곳·키즈존)는 공식 홈페이지·안내문을 **사람이 직접 보고** 체크한다
  (자동 수집 금지 — CLAUDE.md 9장)

## 6. 마무리

1. 승인 장소로 AI 루트 만들기 → `npm run places:export` → `docs/ai-routes.md`
2. 샘플 지우기 (SQL Editor):
   ```sql
   delete from wooz_trip_ai_routes where code like 'sample-%';
   delete from wooz_trip_places where is_sample;
   ```
3. 유지: 사용자 제보 처리, 몇 달에 한 번 `collect list/detail` + `build` 다시 실행해서 바뀐 정보 반영
